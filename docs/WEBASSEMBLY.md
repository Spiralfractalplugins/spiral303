# WebAssembly-сборка (WCLAP)

Spiral303 собирается ещё и как **WCLAP** — CLAP-плагин, скомпилированный в
WebAssembly. Один файл работает и в браузере, и в нативных DAW.

- **в браузере** — через [browser-test-host](https://github.com/WebCLAP/browser-test-host)
  (AudioWorklet + `clap-audionode`);
- **в нативных DAW** — через [wclap-bridge](https://github.com/WebCLAP/wclap-bridge):
  это мост-плагин на Wasmtime, он показывает интерфейс WCLAP как обычное окно.

Формат описан в [WebCLAP](https://github.com/WebCLAP): модуль экспортирует
`clap_entry` (i32-глобал с адресом `clap_plugin_entry`), расширяемую таблицу
функций, память и `malloc`.

## Сборка

```sh
tools/build_wclap.sh
```

Скрипт сам скачивает wasi-sdk в `vendor/` (версия и контрольная сумма
закреплены), собирает модуль и пакует бандл:

```
 dist/Spiral303-<версия>-wclap.tar.gz  — бандл для раздачи
 dist/Spiral303-<версия>-wclap/         — он же, распакованный
    Spiral303.wclap/
        module.wasm                     — сам плагин
        index.html, app.js, style.css   — интерфейс
```

Нужен `cmake` (≥ 3.24) и `python3` (встраивает пресеты и страницу в модуль).
Сборка идёт отдельным проектом `wclap/`, потому что toolchain другой: вместо
компилятора хоста — wasi-sdk.

Ручная сборка, если sdk уже лежит в `vendor/`:

```sh
cmake -S wclap -B build-wclap \
      -DCMAKE_TOOLCHAIN_FILE="$PWD/vendor/wasi-sdk-34.0-arm64-macos/share/cmake/wasi-sdk-p1.cmake" \
      -DCMAKE_BUILD_TYPE=Release
cmake --build build-wclap
```

## Проверки

```sh
wclap/tools/check_wclap.sh
```

Шесть проверок плюс разбор архива:

1. модуль грузится хостом и делает звук;
2. интерфейс отдаётся из памяти плагина и отвечает на сообщения;
3. **все расширения заполнены** — обходятся `clap.gui`, `clap.webview/3`,
   `clap.params`, `clap.audio-ports`, `clap.state`, и каждый слот должен
   указывать на функцию. Хост читает эти указатели напрямую: пустой слот — это
   трап, а сообщение о нём выглядит как «null function pointer at 117660»
   (адрес слота в памяти модуля, openDAW);
4. окно создаётся только на «webview», размер отдаётся нативный (1180×780) вместе с
   подсказкой о пределах resize (900×600…3200×2000),
   неизвестный id расширения возвращает пусто, второй инстанс плагина играет,
   soak на 2000 блоков остаётся конечным;
5. страница рисует себя и ведёт себя как нативный редактор: `check_ui.mjs` прогоняет
   её код против canvas-заглушки без браузера — геометрия, сетка гейта, привязка
   меню к контролам, жесты ручки/сетки/АЧХ, клавиши и user-пресеты (58 проверок);
   фикстура — те же сообщения, что плагин шлёт на `hello` (`dump_state.mjs`); без
   сборки ту же пару сообщений делает `make_state.mjs` из `ParamTable.cpp`. Оба
   сообщения снимаются на лету: `WebView::send()` переиспользует один буфер, а в
   wasm-таблицу JS-функцию не положить, поэтому тестовый хост ставит туда
   60-байтовый трамплин, чей импорт уже пишет лог;
6. рендер wasm-сборки совпадает с рендером нативной: пики идентичны, сэмплы
   расходятся на ~1e-06 — это разница между двумя математическими библиотеками.

Отдельно проверяется, что состояние переезжает между сборками: wasm пишет
файл состояния, нативная сборка его читает и видит те же значения.

Пункт 3 — главный: он ловит ровно тот класс ошибок, из-за которого окно не
открывалось в openDAW, и ловит его локально, без хоста.

## Импорт в openDAW

В openDAW («Import WebCLAP...») бандл импортируется **только архивом целиком** —
`dist/Spiral303-<версия>-wclap.tar.gz`. Голый `module.wasm` хост принимает как
плагин без интерфейса: окно открывается, но страницы в бандле нет, и оно остаётся
чёрным — хост отвечает на отсутствующий `index.html` ошибкой.

Как устроен архив, фиксирует проверка `wclap/tools/check_bundle_tar.mjs`, её
гоняет `check_wclap.sh`. Она повторяет разбор архива из openDAW
(`WclapBundles.untar/stripRoot`) и требует:

- один верхний каталог `Spiral303.wclap/`, и у каждого пути есть «/» — иначе
  хост не обрезает префикс и не находит `module.wasm` («is not a WebCLAP
  bundle»);
- записи только для обычных файлов: без каталоговых записей, без
  pax-заголовков, без AppleDouble `._`-файлов. Всё это пишет системный
  `tar czf` на macOS: корневой `._Spiral303.wclap` без «/» ломает первый пункт;
- в корне после обрезки — `module.wasm` с валидной wasm-магией и `index.html`,
  иначе окно будет чёрным;
- детерминированные байты: та же упаковка дважды даёт тот же файл — хосты,
  адресующие бандлы по хэшу, видят тот же плагин.

Упаковка идёт через `tools/pack_wclap.py` (ustar, отсортированные пути,
mtime/uid/gid = 0, gzip без имени файла и с mtime 0), а не через системный
`tar` — так архив под macOS и под Linux в CI получается побитово одинаковым.

## Чем отличается от нативной сборки

| | Нативная (VST3/AU/CLAP) | WebAssembly |
|---|---|---|
| Интерфейс | JUCE, окно хоста | страница, `clap.webview/3` |
| Темп и транспорт | `PlayHead` хоста | только свой BPM: в CLAP 1.2.7 нет расширения для чтения темпа, так что `Sync = Host` сводится к ручному |
| Пресеты пользователя | файлы в `%APPDATA%/Spiral303/Presets/` | хранилище браузера (страница шлёт текст пресета плагину) |
| Импорт MIDI | файл `.mid` | страница читает файл сама и шлёт готовый паттерн |
| Состояние | JUCE-XML в бинарном контейнере | тот же формат: сессия переезжает между сборками |

Параметры, их значения, диапазоны и состояние — те же самые: id параметров в
state-файле совпадают с нативными, так что пресет или сессия открывается в
любой из сборок.

## Как устроено

```
Source/dsp/            — DSP-ядро (общее у обеих сборок)
Source/core/JuceLite.h — мини-JUCE для сборки под wasm: JUCE сам под wasm не
                          собирается, а ядру нужны только clamp'ы, константы,
                          генератор случайных чисел и строки
Source/wclap/          — CLAP-слой: параметры, состояние, пресеты, часы
web/                   — страница интерфейса
wclap/                 — сборка модуля, хост для тестов, скрипты
```

Ядро собирается дважды: в нативной сборке — против настоящего JUCE, в
wasm-сборке — против `JuceLite.h`. `tests/TestCoreParity.cpp` рендерит один и
тот же паттерн через обе версии и сравнивает сэмплы: они совпадают бит в бит,
и тест падает, если это перестанет быть так.

## Использование в нативных DAW через wclap-bridge

Бандл работает в нативных DAW (Reaper, Bitwig, Ableton и т.д.) через
**wclap-bridge** — мост-плагин на Wasmtime, который оборачивает WCLAP в
обычный CLAP/VST3. Мост устанавливается один раз и затем подхватывает любой
`.wclap`.

### Установка моста

1. Скачать свежий релиз с
   https://github.com/WebCLAP/wclap-bridge/releases (macOS universal,
   Windows x86_64, Linux x86_64).
2. Распаковать и положить `wclap-bridge-plugin.vst3` (или `.clap`) в
   системную папку плагинов (`~/Library/Audio/Plug-Ins/VST3/` на macOS,
   `C:\Program Files\Common Files\VST3\` на Windows).
3. Перезапустить DAW и просканировать плагины.

### Загрузка Spiral303

Мост ищет бандл по имени: распакуйте `dist/Spiral303-<версия>-wclap.tar.gz`
рядом с мостом или укажите путь в настройках моста (зависит от версии моста;
в v0.0.6 мост открывает диалог выбора папки `.wclap` при первом запуске).

Итоговый путь должен содержать `Spiral303.wclap/module.wasm` и
`Spiral303.wclap/index.html` — иначе окно останется чёрным.

### Ограничения

- Темп и транспорт в CLAP 1.2.7 не читаются wasm-модулем: `Sync = Host`
  сводится к ручному BPM (как и в браузере).
- CPU примерно в 1.5 раза выше, чем у нативной сборки (оценка авторов моста).
- Интерфейс отдаётся из памяти плагина через `clap.webview/3`, поэтому
  встроенный браузер хоста нужен; в старых DAW окно может не открыться.
